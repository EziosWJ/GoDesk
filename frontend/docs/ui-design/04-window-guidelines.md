# 04 · 窗口规范

WMKit 负责窗口存在、大小、位置、显示阶段和层叠顺序。React 负责标题栏、应用内容和组件焦点。Windows 提供标题栏行为参考，HarmonyOS 提供窗口构成、可恢复边缘和主辅窗口的参考。HarmonyOS 建议结合标题栏与工具栏来节省空间，React Web Desktop 将它们分工并且仅在视图确有操作时渲染工具栏。 [Windows 标题栏](https://learn.microsoft.com/en-us/windows/apps/design/basics/titlebar-design) · [HarmonyOS 窗口框架](https://developer.huawei.com/consumer/cn/doc/doccenter-ux-design/window-0000002321868010/)

HarmonyOS 原生窗口框架将 1200 × 800 vp 列为默认尺寸参考，最低基线为 360 × 240 vp，并按标题栏内容提供 40、56、64、72 vp 四档。这些值用于理解原生规格的分层。React Web Desktop 使用 CSS px 定义自己的窗口参数。 [HarmonyOS 窗口框架](https://developer.huawei.com/consumer/cn/doc/doccenter-ux-design/window-0000002321868010/) · [HarmonyOS 像素单位](https://developer.huawei.com/consumer/cn/doc/HarmonyOS-references/ts-pixel-units/)

## 尺寸与摆放

- 尺寸基线见 [02](02-design-tokens.md)。首次打开使用通用建议或有明确内容依据的应用首选尺寸，按工作区约束；尽量完整可见，优先避开已有窗口关键区域。应用若需要更大的最小尺寸，须先证明内容不能在 [08](08-responsive-guidelines.md) 的单区视图完成。
- 普通窗口支持标题栏拖动和八方向缩放。缩放热区可透明，指针回馈对应游标，边框仅 1 px。移动时至少保留一段可抓取的标题栏。应验证屏幕左、右和底部极限位置仍有至少 48 CSS px 横向可抓取标题区，避免一侧只剩控制按钮。48 CSS px 为 React Web Desktop 验收建议，WMKit 的 `minVisible` 仅是初始约束。
- 视口变化后，最大化窗口跟随工作区，普通窗口优先保持用户设置的大小并重新钳制至可找回。恢复前按当前工作区校验几何。工作区容纳不了最小尺寸时，按 [08](08-responsive-guidelines.md) 切换移动端应用视图或低高度模式。
- 每个内置应用默认一个主窗口。同一任务需要补充信息时，用检查器或详情；并行的独立任务可切换不同应用窗口。

## 标题栏

精细指针标题栏使用 [02](02-design-tokens.md) 的尺寸。起始侧放应用图标和名称，长标题省略且可读取完整名称。末端顺序为「最小化」「最大化 / 还原」「关闭」，控制区不随标题换行或截断。触控时每个可操作控制至少 44 × 44 CSS px，容器允许增高。自然状态弱化控件背景，激活状态用标题栏表面和窗口边界区分，悬停关闭按钮使用危险语义。

标题栏视觉上留出可抓取区域。窗口控制、交互控件和内容区不参与拖动。双击可抓取的标题栏切换最大化与还原。提供可见的窗口命令入口，含移动、调整大小及移回可视区域，支持键盘和单指针替代操作。最大化窗口保持任务栏及工作区边界，使用 0 圆角并清除外部阴影。

## 生命周期与层级

| 操作 | 结果 |
| --- | --- |
| 打开 / 激活 | 新窗口进入前景，同应用已有实例时激活原窗口。点击可见窗口转到前景，点击控件时仍完成控件的原有操作。 |
| 最小化 | 工作区隐藏窗口，保留内容状态、几何及之前的显示阶段。任务栏项仍可用，键盘焦点转给合理的下一窗口或该任务栏项。 |
| 最大化 / 还原 | 最大化填满工作区。还原优先回到先前的普通窗口几何，必要时根据可用工作区修正。最大化后最小化，再从任务栏恢复仍为最大化。 |
| 关闭 | 释放窗口及关联浮层，移除任务栏项。有可能丢失未保存内容时，说明后果并询问是否继续。焦点转向合理的下一窗口或启动入口。 |

堆叠顺序从底到顶为桌面、普通窗口及其所属浮层、外壳浮层、任务栏、Web 桌面模态弹窗。窗口自己的浮层随所属窗口堆叠，普通窗口不能通过自行增大 `z-index` 覆盖任务栏。外壳浮层避让任务栏。Web 桌面模态弹窗是唯一阻断整个外壳的层，包括键盘和任务栏，通常以发起窗口为定位参考。其他窗口状态保持，弹窗关闭后恢复焦点。检查器默认留在窗口内，与主区可同时操作。 [06 基础组件](06-component-guidelines.md)

## 窗口开合动效

- 各启动入口共用同一动效。创建新窗口时，窗口从最终位置下方 8 CSS px 向上滑入并淡入，用浮层时长（180 ms）。
- 关闭窗口时原地淡出，用反馈时长（120 ms）。有未保存内容时，确认关闭后才开始淡出。
- 两种过渡均使用 `ease-out`。已有窗口的激活、最小化以及从最小化恢复均即时完成。 [设计 Token](02-design-tokens.md#尺寸与动效)
