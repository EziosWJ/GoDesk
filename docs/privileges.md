# 主机权限契约

## 运行身份与部署

- goDesk 以启动它的 Linux 账号运行。以 root 启动时直接使用 root 权限。普通运行账号需要提权时，统一通过 `sudo -n -k -u root` 执行；接受系统已配置的免密授权。程序不保存密码、不弹出密码提示，也不使用已有的 sudo 凭据缓存。
- 启用免密 sudo 或以 root 运行后，goDesk 是被管理主机的管理员入口。操作者能通过终端获得主机 root 权限。部署者在受信任的访问环境中完成首次初始化，沿用现有[操作者认证](authentication.md)。
- 后端默认监听 `0.0.0.0:5000`，可通过 `-listen` 指定地址。Vite 开发代理将 `/api` 和终端 WebSocket 转发到 `127.0.0.1:5000`。

## 主机命令

这些命令在主机终端运行，完成后退出。

| 命令 | 调用身份与结果 |
| --- | --- |
| `sudo ./godesk --setup-sudo` | 由日常运行 goDesk 的普通账号通过 sudo 发起，创建该账号的 GoDesk 托管规则。 |
| `./godesk --check-sudo` | 以当前账号检查免密 root 命令是否可用，并单独报告 GoDesk 托管规则的状态。 |
| `sudo ./godesk --remove-sudo` | 由规则授权的普通账号通过 sudo 发起，移除自己的托管规则。root 可从自己的 Shell 直接执行 `./godesk --remove-sudo`。 |

### 初始化与移除

- 初始化要求有效 UID 为 `0`，从 `SUDO_USER` 和 `SUDO_UID` 识别原始调用者，并用 Linux 账号记录核对名称与 UID。缺少信息、记录不一致或原始调用者是 root 时失败。
- `/etc/sudoers.d/godesk` 只为一个普通账号授予 `NOPASSWD: ALL`。文件归属为 `root:root`、权限为 `0440`。同一账号重复初始化时，校验已存在的有效规则并返回成功。其他账号发起初始化时失败。更换账号时，先撤销旧规则，再由新账号初始化。
- 发布前用 `visudo` 检查待写规则。原子发布后再检查系统实际加载的 sudoers，确认该文件已纳入加载并核对文件归属和权限。加载或校验失败时撤下本次新增文件。安装与移除须避免并发调用覆盖或撤销另一调用刚写入的规则。权限文件的写入范围限于 `/etc/sudoers.d/godesk` 及其安装临时文件。
- 如果 `visudo` 的成功输出仅列出主文件，goDesk 通过 `/etc/sudoers` 中直接指向规则文件或 `/etc/sudoers.d` 的标准包含指令确认加载。
- 路径是符号链接、文件类型不符或内容无法识别为托管规则时，初始化和移除均失败，由主机管理员处理冲突。普通账号通过 sudo 移除时也核对调用者身份和规则所属账号。规则不存在时，重复移除成功。
- 移除规则无需重启 goDesk。仍在运行的 root 子进程可以执行完；后续命令由 sudo 按剩余主机规则判定。批量文件操作保留已完成项的结果，逐项报告后续操作的结果。

### 状态检查

- 普通账号执行 `--check-sudo` 时，以一条无副作用的命令探测能否免密以 root 执行。探测成功退出 `0`，失败退出非零。探测结果只针对该命令，实际操作各自接受 sudo 的授权检查。root 直接执行时显示当前已是 root，退出 `0`。
- 托管规则状态单独报告。能核实时，区分本账号已授权、其他账号已授权、规则不存在和规则异常。当前身份无法读取或核实规则时，显示无法核实。该状态独立于退出码，例如移除托管规则后，主机原有授权仍可让探测成功。

## 操作范围

| 功能 | 普通账号运行时的权限行为 |
| --- | --- |
| 文件管理器和文本编辑器 | 按窗口或文本标签页的身份发起操作。管理员身份经 sudo 调用同一个 `godesk` 二进制的短时子进程，每次只执行一个固定类型的文件操作，结束后退出。详见[文件管理和文本编辑契约](file-management.md#管理员模式)。 |
| systemd 启停、重启、启用和禁用开机自启 | 免密 root sudo 可用时走 sudo；不可用时沿用运行账号原有的非交互执行路径，保留主机 polkit 授权。sudo 已受理的动作失败时直接报告结果，避免再次执行写操作。 |
| 服务列表和 journal 日志 | 以运行账号读取，沿用主机已有的读取权限。 |
| 终端 | Shell 沿用运行账号。操作者可在 Shell 内自行执行 `sudo`。 |

所有文件和服务请求沿用现有的操作者会话认证。提权子进程只处理后端选择的文件操作，复用现有文件逻辑，无需额外安装 root 程序或运行常驻 root 服务。
