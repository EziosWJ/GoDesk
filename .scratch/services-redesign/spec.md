# goDesk 服务管理重设计 Spec

状态：已批准并实现（2026-11-23）

## 背景

用户反馈当前「服务管理」界面设计不佳：搜索/筛选区位于顶栏最右，与列表相距整屏；列表信息密度低（只有服务名与状态，两列间大片空白）；层级冗余（外壳标题 + 应用内大标题 + 工具栏）；详情与日志区有拼装感（标题重复、灰底日志框、重复刷新按钮）。

决定推倒现有方案，重做 Services 应用的前端信息架构与视觉，并按需扩展后端。

本 spec 取代 `.scratch/services/spec.md` 中「前端」与「实现拆分」部分的 UI 方案；该 spec 的后端接口、权限模型、systemd 实现、错误映射仍然有效，本文档在其上追加单服务详情端点。

## 目标

- 筛选与列表同区：筛选工具栏紧贴列表上方。
- 提高扫读效率：两行式列表、状态徽章、开机自启标识、计数 chips。
- 统一视觉：克制的现代桌面工具风格，复用现有 token、图标与明暗主题。
- 保持现有安全模型：不改认证、权限模型与命令调用方式。

## 范围

做：

- 重写 `frontend/src/Services.tsx` 及其子组件与样式（`frontend/src/styles/services.css`），删除 `App.css` 中的旧服务样式与死代码（保留共享的 `.service-dialog`）。
- 新增后端单服务详情端点 `GET /api/v1/services/{unit}` 与 `systemctl show` 解析。
- `frontend/src/services.ts` 增加详情类型与客户端方法。
- `frontend/src/apps.ts` 中服务窗口默认尺寸 720×480 → 1000×640。
- 文档更新与手工验证。

不做：

- 新增深色模式（明暗主题已存在，必须都适配）。
- 日志轮询 / 实时跟随（跟随 = 加载后自动滚到底）。
- 虚拟列表、分页、服务端筛选（~200 行客户端处理）。
- 依赖图 / impact 文案、unit 文件编辑、mask/unmask、i18n。
- 前端测试基建。
- 应用外壳（标题栏、任务栏、窗口管理器）改动。
- 现有动作 / 日志 API 的契约变更。

## 已确认决策

### 布局

- 只重做 Services 应用内部，外壳不动。
- 删除应用内大标题行（原「systemd 服务 / N 个服务」）。
- 左栏顶部为两行筛选工具栏，其下是服务列表；应用底部一条状态栏（左：后端名；右：更新于 HH:MM:SS）。
- 保持左右分栏（列表 / 详情+日志），默认比例 40/60，可拖拽，双击复位；左栏最小 320px、右栏最小 420px、分隔条 6px，分栏阈值 746px；窗口更窄时进入串行模式（列表 ↔ 详情，详情内有「返回列表」）。
- 默认窗口尺寸 1000×640。

### 工具栏与筛选

- 第一行：搜索框 + 刷新按钮 + 排序菜单；第二行：状态 chips。
- chips：全部 / 运行中 / 未运行 / 异常，各带计数；未运行 = 已停止 + 已完成；异常 = 失败 + 未知（含过渡态）。行内徽章始终显示具体状态。
- 计数基于当前搜索结果计算（不受所选 chip 影响）。
- 搜索：服务名 + 描述，大小写不敏感子串，约 100ms 防抖，与 chips 为 AND 关系，命中文本高亮。
- 排序：默认名称升序；「异常置顶」开关把失败/未知置前，其余按名称。
- 后端为 `none` 时隐藏工具栏控件，显示解释性空状态（保留现有文案）；`stateReliable=false` 的警告保留在列表上方。

### 列表

- 两行式行（约 44px）：第一行 服务名（等宽字体、中性色）+ 开机自启小圆点 + 右对齐状态徽章；第二行 描述（灰色、单行截断）。
- 状态徽章 = 图标 + 文字（不单靠颜色）：运行中=success、已完成=accent、已停止=muted、失败=danger、未知=muted。
- 单选；列表获得焦点时 ↑↓ 即时切换选中并同步右侧详情，无需回车；不做多选。
- 刷新后保持选中项与滚动位置；选中服务被筛掉时显示现有提示「此服务已移出当前筛选结果。」
- 搜索无结果时显示空状态 +「清除筛选」。
- 不做虚拟化，直接渲染过滤后的全部行。

### 详情

- 头部：unit 名（等宽、可聚焦）+ 状态徽章；动作区紧随其后；下方为「详情 / 日志」tabs（`capabilities.logs=false` 时无日志页）。
- 动作：启动/停止（按当前状态决定主按钮语义）+ 重启 +「开机自启」开关。可用性来自后端 `actions`；不可用动作**禁用并提示原因**，不隐藏。
- 确认：「停止 / 重启 / 禁用」二次确认（复用共享 `.service-dialog` 模式，不改其全局观感）；「启动 / 启用」直接执行。
- 进行中：禁用该服务动作并内联显示「正在启动/停止/重启服务…」；失败内联 `role="alert"`；401 沿用整页重载。
- 详情页三组键值网格：概述（描述、状态、原始状态、开机自启）、运行（主 PID、内存、CPU 累计时间、启动时间）、文件（unit 文件路径）；空值显示「—」。
- 详情数据来自新端点，在选中变化、列表刷新、动作后拉取。

### 日志

- 每次加载 `lines=500`（沿用现有参数，上限 1000）。
- 加载时机：切到日志 tab、日志打开时切服务、工具栏刷新、动作完成后。
- 「跟随尾部」开关默认开：加载后自动滚到底；关闭时保持滚动位置。本期无日志轮询。
- 行内搜索：客户端过滤已加载行并高亮，显示匹配数；无匹配显示空状态。
- 换行开关默认开；关闭时横向滚动。
- 复制按钮复制全部已加载行。
- 移除日志面板内的「刷新」按钮；空状态「暂无日志」；错误内联。

### 刷新

- 打开时加载；窗口未最小化且页面可见时每 10s 轮询（沿用现有 `active` + `visibilityState` 机制）；窗口聚焦/可见性恢复触发立即刷新；提供手动刷新。
- 动作成功后立即刷新列表、当前详情与（若打开）日志。
- 刷新不打断选中与滚动位置；跟随开启时日志加载后滚到底。

### 视觉

- 现代桌面工具风格：克制、细边框、紧凑、低饱和；颜色仅用于状态徽章等语义位置；unit 名、日志与键值使用等宽字体。
- 复用 `styles/theme.css` 的 token、Lucide 图标、既有原生控件与 dialog 模式；明暗两套主题都要验证。
- 不引入新组件库；不引入前端测试基建。

## 后端设计

### 新端点 GET /api/v1/services/{unit}

```json
{
  "name": "ssh.service",
  "state": "running",
  "stateDetail": "active (running)",
  "bootState": "enabled",
  "mainPid": 1234,
  "memoryBytes": 13844480,
  "cpuUsageNs": 2391500000,
  "activeEnterTimestamp": "Fri 2026-11-21 10:00:00 CST",
  "fragmentPath": "/usr/lib/systemd/system/ssh.service"
}
```

- 命令：`systemctl show -p ActiveState,SubState,UnitFileState,MainPID,MemoryCurrent,CPUUsageNSec,ActiveEnterTimestamp,FragmentPath -- <unit>`；`LC_ALL=C`、绝对路径、不经 shell。
- `state` / `stateDetail` 沿用旧 spec 的状态映射；`bootState` 由 `UnitFileState` 沿用旧映射计算。
- `mainPid`：0 或空 → `null`；`memoryBytes` / `cpuUsageNs`：`[not set]`、非数字或超范围 → `null`；`activeEnterTimestamp` / `fragmentPath`：未设置 → `""`（时间戳原样显示，不解析）。
- 单元不存在 → 404 `not_found`；权限、超时与命令失败映射沿用现有错误表；超时 10s。
- 与动作/日志端点不同，本端点**不先调用 `List`**，直接执行 `systemctl show`，避免一次全量枚举。
- `Backend` 接口增加 `Detail(ctx, unit) (ServiceDetail, error)`；`none` 后端返回 not_found。
- 单元名校验复用 `ValidUnit`。
- 测试：show 输出解析（普通 / exited / `[not set]` / 超范围数字）、handler 200/400/404/403/422/504、`none` 后端 404。

### 前端数据层

- `frontend/src/services.ts` 增加 `ServiceDetail` 类型与 `servicesApi.detail(unit)`，错误仍走 `ServiceError`。

## 实现拆分

1. **后端单服务详情端点** — 接口、systemd `show` 解析、路由、错误映射、测试。
2. **前端页面骨架与工具栏** — 重写 `Services.tsx` 布局、两行工具栏、chips、搜索、排序、状态栏、串行/分栏、10s 轮询与聚焦刷新、窗口默认尺寸、CSS 基础、移除旧样式与死代码。
3. **前端列表** — 两行式行、徽章、自启点、选中与 ↑↓、异常置顶、空状态、命中高亮、刷新保持状态。
4. **前端详情与动作** — 详情端点接入、三组键值网格、动作按钮与禁用原因、确认框、busy/错误、开机自启开关。
5. **前端日志** — 500 行、跟随、行内搜索、换行、复制、加载时机。
6. **文档与验证** — `docs/services.md` 新端点与 UI 行为、README 相关更新、构建/测试、手工验收清单。

## 验收条件

- 筛选工具栏紧贴列表顶部，无跨屏空白；应用内无重复标题层。
- 两行式列表、右对齐徽章、自启小点、状态栏（后端名 + 更新时间）齐全。
- chips 计数与分组语义正确（未运行 / 异常）。
- 详情页三组字段来自新端点，空值显示「—」。
- 动作不可用禁用并给出原因；停止/重启/禁用确认；busy 与错误反馈。
- 日志需求全部满足，且无日志轮询、无重复刷新按钮。
- 10s 可见轮询 + 聚焦刷新 + 手动刷新 + 操作后刷新；选中与滚动保持。
- 746px 阈值与串行模式；默认窗口 1000×640；明暗主题均正常。
- 构建与测试命令全部通过；现有认证、文件、终端、监控功能不受影响。

## 已知取舍

- 详情端点每次拉取执行一次 `systemctl show`；轮询刷新时对选中服务也拉取，可见期间约每 10s 三次 systemctl 调用（列表两次 + show 一次）。
- `activeEnterTimestamp` 按 `LC_ALL=C` 原始字符串显示，不做本地化解析。
- 未加载单元的 Description 仍为空（沿用旧取舍）。
- 日志无实时跟随；「跟随」只作用于每次加载后的滚动位置。
- 列表无虚拟化；~200 行可直接渲染。
- 仅做字节→人类可读单位的客户端换算。
