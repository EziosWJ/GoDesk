# 08 · 响应式规范

视口决定桌面外壳与窗口模式，应用容器决定内部布局。大屏上的小窗口仍然使用紧凑应用布局。HarmonyOS 的官方窗口断点和原生布局提供参考，React Web Desktop 的阈值用 CSS px 表达。 [HarmonyOS 应用设计](https://developer.huawei.com/consumer/cn/doc/doccenter-ux-design/app-design-0000002353509845/) · [HarmonyOS 响应式布局](https://developer.huawei.com/consumer/cn/doc/best-practices/bpta-multi-device-responsive-layout/) · [Tailwind CSS Responsive design](https://tailwindcss.com/docs/responsive-design)

## 外壳与窗口模式

| 条件 | 行为 |
| --- | --- |
| 视口宽度 ≥ 640 CSS px，工作区能容纳浮动窗口最小高度 | 桌面模式。支持浮动、多窗口切换和最大化，任务栏保留。 |
| 视口宽度 < 640 CSS px，或旋转、缩放等使稳定工作区低于最小窗口高度 | 单窗口呈现。活动应用贴合工作区，其他应用在任务栏中可切换。保留应用标识和关闭入口，隐藏拖动、缩放、最小化与最大化控件，用任务栏和开始菜单返回或切换。 |

工作区先扣除任务栏与安全区。移动端利用动态视口高度与安全区变量适配浏览器栏位置。软键盘打开时让输入、提交和取消保持可达，避免临时键盘高度变化触发窗口模式切换。触控优先根据输入能力扩大目标，宽屏触控设备仍可使用桌面模式。低高度单窗口模式与窄宽模式使用同一套窗口操作规则。

切换模式前保留普通窗口几何及当前显示阶段。返回桌面模式时校验几何。只呈现活动应用的模式仍保留其他已打开应用的输入、选择和滚动上下文。若活动应用关闭，选择合理的下一窗口或返回桌面。窗口与任务栏共享 WMKit 生命周期状态。

## 应用容器

测量窗口内承载布局的内容根容器的内联尺寸，位于窗口边框内且在应用自身内边距之前。断点决定可用的布局上限，应用按任务复杂度选择布局。通栏应用在宽容器中可保持通栏。

| 内容根容器宽度 | 布局能力 | 导航与辅助内容 |
| --- | --- | --- |
| < 600 CSS px | 通栏 / 顺序浏览 | 当前任务主视图优先，导航使用具名入口，详情通过串行视图或可关闭的辅助面板访问。 |
| 600 至 < 960 CSS px | 双分栏 | 采用导航＋主区或列表＋详情。检查器按需开启，保留最小主区宽度。 |
| ≥ 960 CSS px | 三分栏 | 有跨栏对照需求时展示第三栏，支持收起。 |

分栏最小值及首选值见 [02](02-design-tokens.md)。若用户增加字号后列宽不足，可主动退回更少窗格。布局根节点用 `@container/app`，子节点使用 `@react-web-desktop-split/app:*` 和 `@react-web-desktop-wide/app:*`。外壳使用媒体查询或同一阈值的窗口模式判断，窗口尺寸与位置由 WMKit 更新。只有确需切换交互模型才在 React 中读取尺寸，纯布局优先 CSS。

## 重排与测试

- 优先保留对象名称、状态与主要操作。低优先级列或操作进入详情和「更多」。需要二维阅读的表格在局部滚动，避免整个桌面出现横向滚动条。
- 缩放和模式切换后保留选择、表单输入、筛选和数据上下文。原控件被收起时，把焦点移动到可见的等价入口。可恢复滚动位置。
- 验证视口 320、360、639、640、1024 与 1280 CSS px。独立验证内容容器在 599/600 和 959/960 CSS px 的变化。覆盖短视口、触控、200% 文本缩放和相当于 320 CSS px 的回流测试。用大屏小窗口验证容器查询。图表、日志和数据表确需二维呈现时约束滚动范围。测试值是 React Web Desktop 建议，回流依据来自 WCAG。 [WCAG 2.2 Resize Text](https://www.w3.org/TR/WCAG22/#resize-text) · [WCAG 2.2 Reflow](https://www.w3.org/TR/WCAG22/#reflow)
