# 07 · 交互规范

同一动作的鼠标、键盘和触控路径使用相同命令、权限和反馈。窗口管理通过 WMKit 执行，React 处理应用组件事件与焦点。

## 鼠标与键盘

| 操作 | 规则 |
| --- | --- |
| 鼠标 | 主键执行显式按钮。桌面快捷方式单击选中、双击打开。右键打开当前对象菜单，空白处打开桌面菜单。 |
| Tab / Shift+Tab | 按任务与阅读顺序移动焦点。菜单等复合组件使用自己的方向键规则。仅模态弹窗限制 Tab 在内部循环。 |
| Enter / Space | 遵循原生按钮和控件语义。Enter 打开已聚焦的桌面快捷方式。 |
| Shift+F10 / 上下文菜单键 | 在控件支持且浏览器把按键交给页面时打开当前对象菜单。关键操作始终有可见入口。 |
| Escape | 先取消当前拖动或缩放，或关闭最上层的可取消浮层。弹窗按取消处理，普通窗口不因此关闭。 |
| 应用快捷键 | 只在所属窗口激活且焦点处于相应作用域时处理。尊重浏览器、操作系统、IME 与文本编辑。对已支持的动作在菜单中展示快捷键。 |

命令菜单打开时聚焦首项。方向键移动，Enter / Space 执行，Escape 关闭并回到有效触发点。Tab 离开并关闭菜单。若声明 `role="menu"`，同步实现 APG 键盘行为和正确的 `menuitem` 语义。开始菜单的搜索与按钮列表遵循 [03](03-desktop-shell.md)。 [W3C Menu and Menubar](https://www.w3.org/WAI/ARIA/apg/patterns/menubar/)

全局桌面快捷键优先提供可见命令做等价操作。禁止把浏览器关闭标签、后退、地址栏或系统任务切换作为 React Web Desktop 必须占用的键。输入法组合期间不触发提交或窗口级快捷键。激活窗口时将焦点引向合理位置，取消浮层或恢复窗口时优先恢复上次有效焦点。

## 拖动与反馈

- 鼠标只在明确可抓取的区域启动窗口移动、缩放或分栏拖动。显示对应游标。用 WMKit 管理窗口指针捕获和拖动轨迹，组件卸载或取消操作时释放各自监听。拖动期间保持邻近操作稳定。
- 窗口菜单提供「移回可视区域」以及移动、调整大小命令。移动和调整大小提供按方向步进的可点击控制与键盘路径，关闭操作面板前可应用或取消。分隔器同样提供可点击尺寸预设或展开收起。若后续增加业务拖放，同时提供菜单或按钮实现等价操作。 [WCAG 2.2 拖动操作](https://www.w3.org/TR/WCAG22/#dragging-movements)
- 悬停作提示，按下提供响应，选中通过稳定标记保持，进行中显示状态。短操作在触发点附近反馈，失败信息给出可执行下一步。窗口焦点样式保持低调，避免整窗闪烁或缩放。 [HarmonyOS 即时反馈](https://developer.huawei.com/consumer/cn/doc/design-guides/toast-0000001929656648/) · [HarmonyOS 进度条](https://developer.huawei.com/consumer/cn/doc/design-guides/progress-0000001929656644/)
- 动效使用 [02](02-design-tokens.md) 的时长。减少动效时关闭装饰性过渡和位移动画，立即更新状态。状态变化使用合适的状态区域，时钟、鼠标轨迹和高频指标采样不做逐次播报。

## 桌面动效验收

打开后界面立即可操作。关闭生效时，退场中的菜单或窗口立即退出焦点顺序，并停止接收指针输入。后续操作可以打断当前动效。

- 从开始菜单启动应用时，菜单退场和新窗口入场同时开始，焦点立即进入应用窗口。应用已有窗口时，立即激活原窗口，菜单照常淡出。 [开始菜单](03-desktop-shell.md#开始菜单) · [窗口开合动效](04-window-guidelines.md#窗口开合动效)
- 开始菜单入场时按 Escape，菜单从当时的视觉状态转为退场，焦点立即回到开始按钮。关闭有未保存内容的窗口时，确认关闭后才开始淡出。
- 开启系统「减少动效」后，开始菜单和应用窗口的打开、关闭均即时完成，焦点行为一致。

## Web 无障碍验收基线

- 普通文本对比度至少 **4.5:1**。大文本至少 **3:1**，WCAG 定义为 18 pt 常规或 14 pt 粗体。识别控件和状态所必需的非文本图形、边界至少 **3:1**。装饰线可使用低对比分割线。 [WCAG 文本对比度](https://www.w3.org/TR/WCAG22/#contrast-minimum) · [WCAG 非文本对比度](https://www.w3.org/TR/WCAG22/#non-text-contrast)
- 焦点应清楚可见，并避免被吸顶控件、任务栏和浮层完全遮挡。React Web Desktop 额外要求可见焦点环与相邻背景至少 3:1。颜色不能成为唯一状态区别。 [WCAG 焦点可见](https://www.w3.org/TR/WCAG22/#focus-visible) · [WCAG 焦点不完全遮挡](https://www.w3.org/TR/WCAG22/#focus-not-obscured-minimum) · [WCAG 颜色使用](https://www.w3.org/TR/WCAG22/#use-of-color)
- WCAG AA 指针目标基线是 **24 × 24 CSS px**，标准定义了间距及其他例外。React Web Desktop 的可交互控件使用更大的规格，缩放边、角和分隔器等窄热区需提供符合尺寸的等价操作。 [WCAG 目标尺寸](https://www.w3.org/TR/WCAG22/#target-size-minimum)
