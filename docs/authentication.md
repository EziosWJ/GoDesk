# 操作者认证

首次访问未初始化的实例时，由部署者在受信任的访问环境中设置密码。第一个成功提交的请求完成初始化并登录。初始化时和网页改密时都需输入两遍新密码。允许任意非空密码，空格会按原样处理。服务将 Argon2id 密码哈希、盐和 JWT 签名密钥保存在 `data/godesk.db`。

JWT 存在持久的 `HttpOnly` Cookie 中，从签发起固定 7 天有效。普通访问不延长有效期。关闭浏览器或重启 goDesk 后，只要所用浏览器仍有有效 Cookie 且服务继续使用原数据目录，就可以恢复会话。浏览器按主机名保存 Cookie，通过 `localhost` 登录后改用 `127.0.0.1` 访问，需要在该地址重新登录。

- 退出登录清除当前浏览器的 Cookie，其他设备保持登录。
- 在「系统设置 → 账户」输入当前密码和两遍新密码。改密成功后，当前浏览器获得新的 7 天会话，旧 JWT 全部失效。
- 忘记密码时，停止服务，在主机上运行 `./godesk reset-password -data-dir ./data`，将数据目录替换为原有路径。终端会隐藏输入，两次输入一致才写入。重置后旧 JWT 全部失效，重启服务后用新密码登录。

## HTTP 接口

接口位于 `/api/v1/auth`，由桌面前端同源调用。所有 POST 请求使用 `Content-Type: application/json`。

| 请求 | JSON 请求体 | 主要结果 |
| --- | --- | --- |
| `GET /session` | — | `200`，返回设置密码、登录或已登录状态。 |
| `POST /setup` | `{"password":"…"}` | `200`，初始化并签发 Cookie。已初始化时返回 `409`。 |
| `POST /login` | `{"password":"…"}` | `200`，签发 Cookie。密码错误时返回 `401`，尚未初始化时返回 `409`。 |
| `POST /logout` | `{}` | `200`，清除当前浏览器的 Cookie，返回登录状态。 |
| `POST /password` | `{"currentPassword":"…","password":"…"}` | `200`，更新密码并签发新 Cookie。会话无效时返回 `401`，当前密码错误时返回 `403`。 |

成功响应的 `status` 为 `setup`、`login` 或 `authenticated`。已登录响应同时返回 RFC 3339 格式的 `expiresAt`。设置密码、登录和改密请求中的 `password` 缺失、为空或 JSON 格式错误时返回 `400`。POST 请求的内容类型错误时返回 `415`。
